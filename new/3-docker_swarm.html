Sizda oddiy index.html bor. Uni internetga qo‘ydingiz. Ertaga saytingizga juda ko‘p odam kirsa yoki server o‘chsa nima bo‘ladi? Docker Swarm — konteynerlarni bitta yoki bir nechta serverda boshqarish vositasi.

version: "3.8"
services:
  web:
    image: swarm-web:v2
    ports:
      - "8080:80"
    deploy:
      replicas: 3
      update_config:
        parallelism: 1
        delay: 5s
        order: start-first
      restart_policy:
        condition: any

package main

import (
    "encoding/json"
    "log"

    "os"

func main() {
    mux := http.NewServeMux()

    mux.HandleFunc("/health", func(w http.ResponseWriter, r *http.Request) {
        w.WriteHeader(http.StatusOK)
        w.Write([]byte("ok"))
    })

    mux.HandleFunc("/api/hello", func(w http.ResponseWriter, r *http.Request) {

            "message": "Salom, Swarm!",
            "hostname": host,
        })
    })

    log.Println("API listening on :8080")
    log.Fatal(http.ListenAndServe(":8080", mux))
}

20-laboratoriya: Swarm xavfsizligi

💡

Esda qoladigan fikr: Cluster portlari private, token maxfiy, TLS va access control alohida ta’minlanadi.

Production’da xizmat ishga tushishi yetarli emas. Cluster’ni kim boshqaradi, qaysi portlar ochiq, parollar qayerda saqlanadi — muhim savollar.

Eng muhim tekshiruvlar

  • 2377/TCP, 7946/TCP+UDP, 4789/UDP faqat ishonchli node’lar orasida ochiq.
  • Docker daemon’ning TCP API’ini internetga ochmang; SSH va access control ishlating.
  • Manager join token’ini maxfiy saqlang va sizib chiqsa aylantiring.
  • Parollar uchun Docker Secret yoki tashqi secret manager; image va Git’da parol bo‘lmasin.
  • Image’larni tekshirilgan registry’dan oling, versiyalarni pin qiling, yangilab boring.
  • Service’ni iloji boricha non-root ishlating; kerakmas Linux capability’larni bermang.
  • Reverse proxy’da TLS/HTTPS va ilova autentifikatsiyasini alohida tashkil qiling.
  • Monitoring, loglar, backup va restore testlarini joriy qiling.

Tokenni yangilash

Manager hostidabash
docker swarm join-token --rotate worker
# Manager tokeni uchun ham alohida rotate mumkin:
# docker swarm join-token --rotate manager

Shifrlangan overlay

Terminalga yozingbash
docker network create --driver overlay --opt encrypted secure-appnet

Bu overlay data traffic’ini shifrlashga yordam beradi (mTLS bilan himoyalangan control plane’dan alohida). Tarmoq throughput’iga ta’sir qilishi mumkin; performance’ni sinab ko‘ring.

443 HTTPS o‘zi kelmaydi

Swarm servisga ports: "443:443" deb yozishning o‘zi sertifikat bermaydi. TLS sertifikat, reverse proxy va yangilanish jarayoni alohida sozlanadi.

21-laboratoriya: Git push → production release

💡

Esda qoladigan fikr: Git push ≠ release; build → push → deploy → verify zanjiri kerak.

Eng ko‘p so‘raladigan savol: “index.html ni o‘zgartirib Git’ga push qilsam, nima uchun serverdagi sayt eski?” Chunki Git, registry va Swarm boshqa-boshqa tizimlar.

Manual release uchun minimal tartib

Bosqichlarga ajratilgan production deploybash

docker build -t YOUR_DOCKERHUB_USER/swarm-web:v4 .

# 4. MANAGERDA qayta deploy
docker stack deploy -c stack.yml demo

# 5. Holatni tekshiring
docker stack services demo
docker service ps demo_web

CI/CD qanday ishlaydi?

  1. Git push bo‘lganda CI job ishlaydi.
  2. Test va lint muvaffaqiyatli o‘tadi.
  3. Image Git commit SHA bilan build qilinadi.
  4. CI registry’ga image push qiladi.
  5. Himoyalangan deploy bosqichi manager’da yangi tag bilan stack deploy qiladi.
  6. Healthcheck va monitoring natijalari tekshiriladi; xato bo‘lsa rollback qilinadi.
Faqat latest tag bilan aldamang

Bir xil latest tagni qayta push qilish va faqat YAML o‘zgarmagan holda redeploy qilish kutilgan roll out’ni bermasligi mumkin. Release uchun yangi tag/digest ishlating va deploy holatini tekshiring.

💡

Esda qoladigan fikr: 3 yoki 5 manager quorum; Swarm backup DB backup o‘rnini bosmaydi.

Quorum bo‘lmasa yangi boshqaruv qarorlari va deployment qiyinlashadi. Mavjud container’lar ishlashda davom etishi mumkin, ammo automatic recovery cheklanishi mumkin.

Swarm manager state backup

Docker hujjatlariga ko‘ra cluster state manager’da /var/lib/docker/swarm/ da saqlanadi. Shu katalogni to‘g‘ri consistency bilan zaxiralash, autolock bo‘lsa unlock key’ni alohida saqlash muhim. Manager backup DB ma’lumotlarini to‘liq backup qilmaydi.

Minimal amaliy reja

  • Manager state backup va muntazam restore testi.
  • PostgreSQL uchun WAL/physical yoki logical backup va tiklash sinovi.
  • Registry image retention va aniq release taglar.
  • Alert: service replicas, failed tasks, disk, RAM, error rate, latency.
  • Node lifecycle: drain → maintenance → active.
  • Secret/token rotatsiyasi va access audit.
Backup ≠ HA

3 ta manager — cluster boshqaruvini bardoshli qiladi. Lekin DB uchun mustaqil backup, failover va restore talablarini almashtirmaydi.
